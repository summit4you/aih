# IDE 与无头接入

AIH 不仅能以交互式终端形态运行，还支持通过无头服务（headless）、MCP 协议和 SDK 嵌入等多种方式接入外部工具和 IDE。本章介绍这些接入方式的原理和适用场景。

## 无头服务：serve 与 attach

`cli/src/serve.ts` 提供了 AIH 的无头服务模式。通过 `aih serve` 启动服务，`aih attach` 连接到已运行的实例，可以实现完全自动化的 AI 交互。

服务暴露以下 HTTP 路由：

| 路由 | 功能 |
|---|---|
| `/health` | 健康检查 |
| `/events` | SSE 事件流 |
| `/message` | 发送消息 |
| `/tools` | 工具列表 |

SSE（Server-Sent Events）流提供实时事件推送，适合构建 Web 界面或监控面板。

## 注入会话的安全约束

通过 `POST /message` 或转向（steering）注入的会话，其 `inputSource` 会被标记为 `"injected"`。这是一个关键的安全边界：**注入的会话永远不能批准权限请求**（CC#60）。

权限确认必须从本地 TTY 终端发起。这防止了远程攻击者通过注入消息来绕过人工确认流程，是 AIH 安全模型的重要组成部分。

## MCP 作为 IDE 桥接

MCP（Model Context Protocol）让 AIH 的工具可以被任何 MCP 客户端使用。通过 `mcp-server` 组件，AIH 的工具可以挂载到：

- **opencode / codex / claude** 等 AI 编程助手
- **VS Code** 等支持 MCP 的 IDE
- 任何兼容 MCP 协议的客户端

当多个 MCP 服务器提供同名工具时，会发生**跨服务器名称冲突**。AIH 的解决方案是自动重命名为 `<server>_<tool>` 格式，确保每个工具都有唯一的标识符。

## 三种集成形态对比

根据不同的使用场景，AIH 提供三种主要的集成方式。三种形态共享同一套核心能力，只是接入层面的不同封装，确保无论哪种方式都能获得一致的功能和安全保障。

> 三种形态各自的入口、适用场景与对照表，已在 [第 8 章「MCP 与接入形态」](ch08) 完整展开，这里不再重复。本章聚焦其中的无头服务（serve/attach）与 MCP 桥接两种形态。
