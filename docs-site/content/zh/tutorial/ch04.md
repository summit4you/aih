# 会话系统

AIH 的会话（Session）是智能体与模型交互的完整记录。理解会话系统，是掌握 AIH 工作流的第一步。

> **先给小白的一句话**：会话日志就好比一本**只往后写、从不涂改**的账本。每一笔事件（你说了什么、模型回了什么、工具做了什么）都被**追加**到账本末尾。想回到过去某个时刻？不是把后面的撕掉，而是**从那一页重新开一本新账**往下记。这样，任何一笔记录都能被找回、被重放、被审计。

## SessionLog：追加式事件流

`SessionLog`（`core/src/session-log.ts`）采用 **append-only JSONL** 格式——每条事件只能追加，不能原地修改。

“追加式”到底意味着什么？下面这段是它的核心接口（做了简化，逻辑与源码一致）：

```ts
class SessionLog {
  append(event): SessionEvent        // 追加一条事件，返回带有序号的事实
  fork(fromSeq = 0): SessionLog      // 从某个历史序号“分叉”出新日志
  checkpoint(name): SessionEvent     // 打一个命名存档点（也是一条事件）
  restoreTo(checkpointSeq): SessionLog  // “回滚”= 只保留到存档点为止的前缀
}
```

关键在于 **回滚不是删除**。`restoreTo(checkpointSeq)` 的实现是：找出最近的 `type === "checkpoint"` 且 `seq <= checkpointSeq` 的事件，然后 `filter(e => e.seq <= checkpointSeq)`——**保留前缀，而不是抹掉历史**。所以：

- **模型可见的内容 = 可重放的事件序列**：凡是影响模型决策的信息，都必须先变成一条事件。没有“看不见的隐藏状态”。
- **回滚 = 前缀分叉（prefix fork）**：从某个历史位置创建新的事件分支，原分支原封不动。
- **崩溃可恢复**：事件一旦写入磁盘就持久化，进程意外终止也不会丢。

## 检查点：给状态“存档”

文本编辑器里的 **Ctrl+Z 撤销**只能退一步；AIH 的检查点则是**命名存档点**：在任意时刻打一个 `checkpoint(name)`，之后随时 `restoreTo` 回到这一刻。因为检查点本身也是一条 append-only 事件，所以“存档”同样可重放、可审计。配合 `cli/src/sessions.ts` 的会话命令（`fork`、`checkpoint`、`restore`），你可以把一次失败的尝试当作从没发生过，回到存档点重新规划。

## 压缩与上下文管理

随着对话增长，上下文窗口会被占满。AIH 提供三种压缩（compaction）策略：

- **主动压缩**：每轮第一步执行前自动 compact，确保模型输入不超过上下文限制。
- **被动压缩**：当上下文超过 `compactAt` 阈值时自动触发。
- **手动压缩**：用户通过命令主动触发。

压缩后的投影通过 **`coverageDigest`** 验证完整性。它的原理是一个 **SHA-256 摘要**（32 位十六进制字符）：压缩时要声称“我覆盖了 `upToSeq` 之前的所有事件”，`coverageDigest(events)` 对这些事件算出一个哈希值；回放时重新计算，**若对不上，这条压缩会被当作“从未发生”**（源码里是 `continue` 跳过）。这保证了压缩结果与它声称覆盖的日志严格一致——模型绝不会因为压缩而看到“与事实对不上的历史”。

```ts
// 回放时的验证（简化）：摘要不匹配 → 假装这条压缩不存在
if (coverageDigest(events.filter(e => e.seq <= event.coverage.upToSeq))
      !== event.coverage.digest) {
  continue; // treat as if this compaction never happened
}
```

## 工具输出上限

为防止单个工具调用消耗过多上下文，AIH 设置了两层限制：

- **单次输出上限** `TOOL_OUTPUT_MAX_CHARS = 8192`：单个工具返回结果的最大字符数。
- **每轮汇总上限** `TURN_TOOL_BUDGET_CHARS = 512000`：单轮内所有工具输出的总字符预算。超出时，最早的结果被保留，超出部分被截断。触发截断时会注入 `TURN_BUDGET_STOP_DIRECTIVE` 提示模型。

## 持久化与会话管理

`session-store.ts` 使用 **临时文件 + 原子重命名**（`#publish`）实现安全写入——先把内容写进临时文件，再一次性重命名为正式文件，避免“写到一半断电”留下半截文件。配合元数据旁路文件和断尾修复（torn-tail repair）确保数据完整性。

会话管理命令（`cli/src/sessions.ts`）支持保存、分叉、查看树形结构、检查点、恢复与续接。在 CLI 中使用 `--session <name>` 指定会话名，`-c` 恢复最近一次会话。CJK 文本的 token 估算约为 1 字符/token，其他语言约为 1 token/3.5 字符。
