# 第12章 CLI 与 TUI

> **先给小白的一句话**：CLI 的 `aih` 命令就像一个**大楼前台的分机总机**——你在门口喊一声 "run"、 "chat" 还是 "tools"，总机（`main()`）先核对你是不是楼里的人（项目信任门），然后把你转给对应分机（`cmdRun` / `cmdChat` / …）。进了 TUI 之后，输入框里的 `/goal`、`/mode` 这些斜杠命令，则是**前台内部的快捷直拨**——命中就直接处理，没命中就当普通对话发出去。

AIH 提供了功能完整的命令行界面（CLI）和终端用户界面（TUI），覆盖从交互对话到后台服务的全场景。本章梳理命令体系、TUI 交互与模式切换。

## 命令体系

AIH 的命令入口在 `cli/src/index.ts`，由 `main` 函数分发到各子命令：

- **aih / aih chat**：启动交互式 TUI 对话
- **aih run**：非交互式执行
- **aih tools**：列出可用工具
- **aih describe**：查看工具详情
- **aih config**：管理配置
- **aih session**：会话管理（`list`、`show`、`export`、`fork`、`checkpoint`、`restore`）
- **aih skills**：技能管理（`list`、`find`、`install`、`show`）
- **aih stats**：查看统计信息
- **aih serve** / **aih attach**：headless 服务与连接
- **aih coverage** / **aih quality**：覆盖率与质量报告
- **doctor --fix**：自动修复常见问题

裸命令 `aih` 需要 TTY 环境才能启动交互对话，否则打印帮助信息。

### 从源码看分发

命令如何找到各自的分支？全部在 `cli/src/index.ts` 的 `main()` 里，三步成型：

```ts
async function main() {
  const { command, positionals, flags } = parseArgs(process.argv.slice(2));
  // 第 1 步：项目信任门 — 在读取任何配置/技能前先确认当前目录是否受信
  const outcome = await ensureProjectTrust({ interactive, flag, defaultPolicy });
  setProjectTrustState(outcome === "granted" ? "trusted" : "untrusted");
  // 第 2 步：版本 / 帮助短路
  if (bool(flags, "version", "v")) { console.log(VERSION); return; }
  if (bool(flags, "help", "h"))   { console.log(HELP);  return; }
  // 第 3 步：无命令时——TTY 直接进 chat，否则打印帮助退出
  if (!command) {
    if (process.stdin.isTTY) return cmdChat(flags);
    console.log(HELP); process.exit(1);
  }
  // 第 4 步：按命令分发到对应 cmd*
  switch (command) {
    case "run":   return cmdRun(positionals, flags);
    case "chat":  return cmdChat(flags);
    case "tools": return cmdTools(flags);
    // … session / skills / workflow / team / mcp / serve …
  }
}
```

读这段的四个体会：

1. **先信任、后解析**：项目受信与否在读取 `aih.json` / 技能之前就定了，未受信的项目配置整轮被忽略——防止恶意仓库借用 CLI 读取敏感配置。
2. **TTY 决定默认行为**：裸 `aih` 在终端里 = 打开交互对话，在管道/CI 里 = 打帮助并退出（非交互 fail-closed）。
3. **switch 即命令路由表**：每个子命令一个 `cmd*` 函数，增删命令就是增删一个 case，职责干净隔离。
4. **`--mock` / `--goal` 只是 `cmdRun` 内部策略**：同一入口承载从离线演示到裁判级自动续跑（`--goal`）的全部形态。


## TUI 界面

TUI 实现位于 `cli/src/tui.ts`，采用 opencode 风格设计。快捷键定义在 `cli/src/keybinds.ts` 和 `tui.json` 中。

核心交互元素包括：

- **Tab / `/mode build`**：在 build 和 plan 模式间切换
- **`/usage`**：查看 token 用量
- **`/goal`**：设置或查看当前目标
- **Context 面板**：显示成本（`$x`）、token 速率（`N tok/s`）
- **状态栏**：显示当前模式和连接状态

Markdown 表格在 TUI 中原生渲染，CJK 字符和 emoji 的宽度通过 `string-width` 正确计算，确保对齐。

## 开发模式语义

`--dev` 和 `--no-dev` 标志控制工具集的可用范围：

- **aih chat**：默认启用本地工具集（`--no-dev` 可关闭）
- **aih run / aih workflow / aih tools**：本地工具集默认关闭，需要显式 `--dev` 开启

这一设计确保生产环境不会意外暴露开发工具。交互式对话更宽松，自动化执行更严格——符合最小惊讶原则。

## 非 TTY 分发

当 `aih chat` 在非 TTY 环境运行时，自动退化为 headless 模式。`aih serve` 启动 HTTP 服务端，`aih attach` 连接到已有服务。这使得 AIH 可以嵌入 CI/CD 管道、远程服务器和容器环境。

## 小结

AIH 的 CLI 和 TUI 设计体现了"渐进式复杂度"：简单命令开箱即用，高级功能通过标志和子命令逐步解锁。无论你是终端新手还是效率专家，都能找到合适的交互方式。更多权限相关配置可参考 [权限配置](../permissions)，核心机制详解见 [第 9 章](ch09)。
