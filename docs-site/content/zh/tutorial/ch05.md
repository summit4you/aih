# 工具系统

AIH 的工具系统是智能体与外部世界交互的桥梁。所有工具通过 `ToolRegistry` 统一注册、查找和调用。

> **先给小白的一句话**：工具就是 AI 的**一双手**——它自己不会读文件、跑命令，全靠调用工具。`ToolRegistry` 就像一个**登记了所有工具的名册**：AI 想干什么，就从名册里点名；点名之后，还要**过五道安检**才真正放行。本章就讲这"名册 + 安检"是怎么实现的。

## ToolRegistry 与 ToolDefinition

`ToolRegistry`（`core/src/tool-registry.ts`）提供 `register`、`get`、`schemas` 和 `invoke` 四个核心方法。每个工具是一个 `ToolDefinition` 对象，它其实是一张"工具使用说明书"：

```ts
interface ToolDefinition {
  name: string;                                  // 工具名字，AI 靠它点名
  description: string;                           // 告诉 AI"这个工具是干嘛的"
  kind: "read" | "write";                        // 读还是写（读可并行、写串行）
  permission: "allow" | "ask" | "deny"           // 三档权限（可写死，也可给函数动态决定）
             | ((args) => ...);
  parameters: ToolSchema["parameters"];          // 参数 Schema，让 AI 知道该传什么
  execute(args, ctx): Promise<unknown>;          // 真正干活的函数
}
```

`register` 的实现很直白——**只是登记，不让重名**：

```ts
register(def: ToolDefinition): this {
  if (this.#tools.has(def.name)) throw new Error(`tool already registered: ${def.name}`);
  this.#tools.set(def.name, def);   // 放入名册
  return this;
}
```

调用 `schemas()` 返回 `ToolSchema` 数组（名字、描述、参数），供模型在"下一步该调哪个工具"时做选择题。

## 守卫管道：一次调用过五道安检

每次调用工具时，`invoke()` 会经过五层守卫。为什么层层设卡？因为 AI 是"外部输入"，它想动的每一下，都应该在**最小权限**下被审视。

<figcaption>一次工具调用的完整守卫路径：解析权限 → doom-loop 守卫 → before 钩子 → 执行 → after 钩子/审计</figcaption>
</figure>

对照源码，`invoke` 的核心步骤可以这样读（简化但忠实）：

```ts
async invoke(name, input) {
  const def = this.#tools.get(name);
  if (!def) return { ok: false, error: this.#planHint
      ? `unknown tool: ${name} — not available in read-only (plan) mode`
      : `unknown tool: ${name}` };                 // 0) 名册里没有 → 直接失败

  const permission = 解析(def.permission);          // 1) 解析权限
  if (permission === "denied")
    return { ok: false, permission: "denied" };     //    denied → 直接拒

  const repeats = this.#countRepeats(name, input);  // 2) doom-loop 计数
  if (repeats >= DOOM_LOOP_DENY_AT)                 //    >=6 次 → 硬拒绝
    return { ok: false, permission: "denied" };     //    >=3 次 → 触发 ask(DOOM_LOOP_ASK_AT)

  await hooks.before(...);                          // 3) before 钩子：脱敏/计时/审计
  const result = await def.execute(input, ctx);     // 4) 真正执行
  await hooks.after(...);                           // 5) after 钩子：结果改写/审计
  return result;
}
```

五道守卫分别是：

1. **权限解析**：将 `def.permission`（静态字符串或函数）解析为放行/拒绝。拒绝则返回 `denied`。
2. **死循环检测**：相同调用重复出现时触发——`DOOM_LOOP_ASK_AT = 3` 时要求用户确认，`DOOM_LOOP_DENY_AT = 6` 时硬拒绝。防止 AI 卡在同一步反复重试。
3. **前置钩子**：执行脱敏、计时和审计；如果触发 `AskError`，强制请求人类确认（CC#53——谁都不能绕过"问人"这一底线）。
4. **执行**：运行 `def.execute` 的实际逻辑。
5. **后置钩子**：结果改写与审计记录。

## 应用工具与内置通用工具

AIH 的工具来自两个来源：

- **应用工具**：由 `AppAdapter` 的 actions 提供（参见 [第 8 章](ch08)）。
- **内置通用工具**（`cli/src/dev-tools.ts` + `general-tools.ts`）：`list_dir`、`read_file`、`write_file`、`run_cmd`、`edit`、`glob`、`grep`、`webfetch`、`websearch`、`task`、`best_of_n`、`question`、`remember`、`load_skill`、`todo`。

当应用工具与内置工具同名时，**应用工具优先**。

## 并行只读执行

为提升效率，AIH 支持并行只读调用（F#29）：连续的只读工具调用会并发执行，上限为 `AIH_TOOL_CONCURRENCY`（默认 4）。写操作始终串行执行。所有结果按原始调用顺序返回，由 `agent-loop.ts` 中的 `mapConcurrent` 实现。

> **为什么读能并行而写不能？** 读只是"看一眼"，同时看多个地方没风险；写会"改东西"，同时改会产生竞争、互相踩踏。所以系统给读发"可以一起上"的通行证，给写发"排队一个一个来"的牌子。
