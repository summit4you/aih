# 插件与扩展系统

AIH 的可扩展性建立在一套统一的插件（extension）架构之上。插件可以注册新的工具、命令，也可以通过钩子（hook）拦截和修改已有工具的输入输出——但所有钩子都运行在审计和脱敏之后，确保安全边界不被绕过。

> **先给小白的一句话**：插件就是**给 AI 工具箱加新工具、或改造现有工具行为的"外挂卡"**。它很强大，所以系统给它规定了明确的站队：**必须先过安检（权限/脱敏/审计），才轮到它动手**。这就好比剧组里再大牌的客串演员，也得先过安保才能进片场。

## 加载流程

插件的加载由 `cli/src/extensions.ts` 中的 `loadExtensions(...)` 函数驱动。启动时，AIH 按以下顺序扫描并加载插件：

1. 项目级插件（`.aih/extensions/` 目录下）
2. 用户级插件（XDG 数据目录下）
3. 内置插件

项目级插件仅在**项目受信**（project trust gate）时才会加载，这是一道重要的安全门控。如果项目未被信任，其插件目录会被完全忽略。这一设计防止恶意仓库通过插件注入代码。

## 工具注册与命令注册

插件通过三个核心 API 与 AIH 交互（`ExtensionApi`）：

```ts
interface ExtensionApi {
  registerTool(def): void;      // 注册一个新工具，出现在模型工具列表
  registerCommand(cmd): void;   // 注册一条新 CLI 命令（TUI /name）
  onEvent(event, handler): void;// 监听生命周期事件
}
```

- **`registerTool`** — 注册一个新的工具，使其出现在模型可用工具列表中。如果注册的工具与内置工具同名，会发生**工具遮蔽**（tool shadowing）：扩展工具取代内置工具，但继承后者的基本渲染行为。
- **`registerCommand`** — 注册一条新的 CLI 命令，扩展命令行界面的功能。
- **`on`** — 注册事件监听器，响应系统生命周期事件。

这三者构成了插件与 AIH 核心交互的完整接口。

## 钩子瀑布流

钩子是插件最强大的能力。通过 `hookSet()` 构建钩子集合，再由 `registry.addHooks(hookSet)` 注册到全局注册表，插件可以在工具执行的前后注入自定义逻辑。

**关键设计：扩展钩子运行在瀑布流的最末端。** 这意味着它们看到的已经是经过脱敏（redaction）和审计（audit）处理的结果，而它们对结果的修改也会被写入日志。**安全层始终在扩展之前执行**——插件能力再大，也绕不过权限门与审计。

支持的钩子事件包括：

| 事件名 | 触发时机 |
|---|---|
| `tool:before` | 工具调用执行前 |
| `tool:after` | 工具调用执行后 |
| `turn:end` | 一个对话轮次结束时 |

通过 `onEvent` API 可以监听这些事件，实现日志增强、结果过滤、自动修复等高级用法。

## AskError：强制人工确认

扩展可以抛出 `AskError` 异常。这不是一个简单的否决——它会触发**人工确认底线**（CC#53），即系统必须等待用户显式批准后才能继续。这比静默拒绝更加透明，适用于插件需要人工审核才能安全执行的场景。

例如，一个部署插件在执行 `apply_patch` 前可以抛出 `AskError`，要求用户确认变更内容。

## 禁用与安全

在不需要扩展能力时，可以通过 `--no-extensions` 标志完全禁用所有插件加载。这在 CI/CD 环境或安全敏感场景下特别有用。

此外，所有扩展钩子的输入输出都会经过审计日志记录，确保任何修改都有迹可循。结合钩子运行在瀑布流末端的设计，AIH 在开放扩展能力的同时保持了可靠的安全边界。
