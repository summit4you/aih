# 第9章 权限控制系统

AIH 的权限系统贯穿每一条工具调用，既保护宿主机器安全，又保留灵活的自动化能力。本章从核心接口到交互细节逐一拆解。

> **先给小白的一句话**：把 AI 看成一个**实习生**。你给他一张权限卡：
> - **allow**（绿卡）——随便做，不用问：比如“看看 README 在不在”。
> - **ask**（黄卡）——动手前先来问你：比如“我能删掉这个文件吗？”
> - **deny**（红卡）——绝对不许做：比如“永远别碰 `.env` 里的密钥”。
>
> 而且规定了一个“**地板**”：红卡一开，谁都不能把它翻绿。这就是全章最核心的一条规则。

## 三层权限模型

每个 ToolDefinition 和 App Action 都支持三种权限层级：`allow`（自动放行）、`ask`（交互确认）、`deny`（直接拒绝）。权限判定由 **ApprovalGate** 接口驱动（`core/src/seams/permissions.ts`），核心方法为 `request(req): Promise<boolean>`。内置实现包括 `AutoApprove`、`DenyAll`、`PolicyGate` 和 `RulesetGate`。

`RulesetGate` 遵循 **优先级地板** 规则：`deny > ask > allow`。这句看起来很抽象，其实就一句话：**后到的规则不能把权限往“放得更松”的方向改。** 如果某条规则将权限提升至 `ask`，后续的 `allow` 规则无法将其降回来——这确保高权限策略不会被低权限规则覆盖（详见 CC#53）。

`PolicyGate` 的判定逻辑可以这样读懂（简化）：

```ts
async request(req): Promise<boolean> {
  for (const rule of this.rules) {
    if (rule.match(req)) {
      if (rule.action === "allow") return true;  // 命中绿卡 → 放行
      if (rule.action === "deny")  return false; // 命中红卡 → 拒绝
      break;                                     // 命中黄卡 → 交给下面去询问
    }
  }
  // 落到 ask：询问用户（没有绿卡能把它降回去）
  return this.fallback.request(req);
}
```

> **一条防糊涂的类比**：优先级地板就像“安全锁只许往更紧拧、不许往更松拧”。一次 `deny` 一旦锁死，后面的任何 `allow` 都拧不开它。

## 规则与作用域

权限规则由三元组定义：`PermissionRule {tool, pattern, action}`。匹配时使用 `matchPattern`（glob 转 regex，`**` 匹配任意路径段，`*` 匹配单段）。作用域通过 `deriveScope` 计算——取目标路径的父目录并附加 `/**`。路径读取器 `targetOf` 支持多种键名：`path`、`file`、`dir`、`directory`、`target`。

这一设计让你可以精确控制：仅允许对 `/app/src/**` 的写入，或仅拒绝对 `.env` 文件的读取。作用域自动继承，无需重复声明。

## SessionGate：交互式审批

`SessionGate`（`cli/src/gate.ts`）处理需要人工介入的权限请求。在 TTY 环境下提供三选一：`[y]es`（本次允许）、`[n]o`（拒绝）、`[a]lways`（本次会话始终允许）。

只读命令会被自动放行——通过 `isReadonlyCommand` 和 `read` 类型判定（**“只是看看”= 默认绿卡**）。对于 WRITE 类型的 shell 命令，SessionGate 提供“运行或复制”模式：你可以选择直接执行、复制到剪贴板（不会执行）、或取消。值得注意的是，注入式输入（`serve`/`attach`）永远不会获得 `ask` 的审批权（CC#60）——见 [第 16 章](ch16) 对注入会话安全约束的说明。

## 项目信任与防死循环

**项目信任**（`cli/src/project-trust.ts`）按目录粒度管理信任状态，存储在用户全局目录的 `trust.json` 中。项目自身无法为自己建立信任。通过 `--trust` 或 `--no-trust` 标志控制，非交互环境下默认拒绝（安全关闭）。目录移动后需要重新授权。

**防死循环保护**位于 tool-registry 中：同一权限请求被连续问 `>=3` 次自动升级为拒绝，`>=6` 次则永久拒绝。这防止工具陷入无限重试的审批循环——**如果 AI 反复想干同一件需要确认的事，系统会替你说“不行”并停下来**。

## 小结

AIH 的权限系统是多层防御：核心层提供策略接口，SessionGate 管理交互体验，项目信任保障目录级安全，防死循环保护系统稳定性。理解这些机制是安全使用 AIH 的基础，也是自定义权限策略的起点。如需更多命令行细节，请参阅 [命令参考](../commands)。
