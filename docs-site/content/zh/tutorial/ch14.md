# 技能系统

> **先给小白的一句话**：技能就是**一张写着"做事方法"的说明书（SKILL.md）**，放在几个约定好的抽屉里（`.aih/skills/`、`~/.aih/skills/`、内置目录）。系统启动时像图书管理员一样，把每个抽屉里的说明书**扫描、拆封面、按书名去重**（`discoverSkills`）；你主动要哪本，它就是**全文借给你**（`load_skill`）；你不开口时，它还能用 BM25 这个"关键词排名器"**猜你可能想要哪本**（`suggestSkills`）。

技能（skill）是 AIH 中最轻量的扩展形式——本质上就是一份 Markdown 文件。它不需要编写代码，任何人都可以创建、分享和使用技能来增强 AI 助手在特定场景下的能力。

## 技能的定义

一个技能就是一个 `SKILL.md` 文件，包含两部分：

- **YAML frontmatter**：声明 `name`（技能名）和 `description`（简短描述）
- **Markdown 正文**：技能的完整指令内容，被加载后作为系统提示的一部分注入上下文

AIH 通过 `load_skill(name)` 工具调用来加载技能。首次调用返回完整文本；同一会话中第二次调用同一技能只返回摘要，避免重复占用上下文空间——这就是 **SkillLoadTracker 去重机制**（CC#52）。

## 三级加载

技能的查找遵循三级优先级，高优先级的同名技能会遮蔽低优先级的版本：

| 优先级 | 来源 | 路径 |
|---|---|---|
| 最高 | 项目级 | `.aih/skills/` |
| 中 | 用户级 | XDG `~/.aih/` |
| 最低 | 内置 | AIH 安装目录 |

这意味着团队可以在项目仓库中放入自定义技能，覆盖全局或内置的同名技能，实现项目级别的定制。

### 从源码看 Discovery 与按名去重

`discoverSkills()` 用一张 `Map<name, Skill>` 逐级合并，**后写入者覆盖先写入者**，天然实现"项目 > 用户 > 内置"：

```ts
export function discoverSkills(projectDir = process.cwd()): Skill[] {
  const byName = new Map<string, Skill>();
  // 用户级先扫（XDG 优先，旧 ~/.aih 垫底）—— 后写覆盖，故主目录优先
  for (const dir of userSkillsDirs()) {
    for (const s of loadSkillDir(dir, "user")) byName.set(s.name, s);
  }
  // 项目级再扫 —— 覆盖同名用户/内置技能（项目定制生效）
  for (const s of loadSkillDir(join(projectDir, ".aih", "skills"), "project")) {
    byName.set(s.name, s);
  }
  // 内置垫底 —— 仅当没有同名技能才补入
  for (const b of BUILTIN_SKILLS) {
    if (!byName.has(b.name)) byName.set(b.name, { ...b, scope: "builtin" });
  }
  return [...byName.values()];
}
```

每个 `SKILL.md` 由 `parseSkillMd()` 解析——用正则切出 YAML frontmatter，逐行读 `name` / `description` / `secretpatterns`：

```ts
const m = /^---\r?\n([\s\S]*?)\r?\n---\r?\n?([\s\S]*)$/.exec(raw);
// m[1] = frontmatter（元数据），m[2] = 正文（被注入系统提示）
// secretPatterns 用分号分隔（不是逗号——避免正则里的 {16,} 被误当分隔）
```


## BM25 自动建议

AIH 内置了基于 **Okapi BM25** 算法的技能自动建议系统（实现在 `cli/src/bm25.ts` 中）。当对话进行时，`suggestSkills` 函数会将当前对话内容与所有可用技能进行相关性排序，自动推荐最匹配的技能。

BM25 的核心参数为 **K1=1.5**、**B=0.75**，并使用 **CJK bigram**（中文/日文/韩文二元组）分词来支持多语言场景。推荐的技能会被写入上下文技能名单（roster），但技能名单严格控制在 **2% 的上下文预算** 以内（`withSkillRoster`），避免推荐机制本身消耗过多上下文。

BM25 为什么能"看懂"中文？看 `cli/src/bm25.ts` 的 `tokenize`——它对连续 CJK 串按**二元组**切分，让子串查询也能命中长句：

```ts
// ASCII 数字/字母 → 单个 token
// 连续 CJK 串（无词界）→ 展开为字符二元组
if (tok.length === 1) out.push(tok);
else for (let i = 0; i < tok.length - 1; i += 1) out.push(tok.slice(i, i + 2));
// 例如 "批量操作" → ["批量","量操","操作"]，"批量操作与验证" 也能被 "批量操作" 命中
```

随后 `buildIndex` 统计每个 token 的文档频率（`df`）与平均长度（`avgdl`），`rank` 把查询 token 与每个技能文档做 **Okapi BM25 打分**：出现越罕见、且与文档长度越匹配的 token，分数越高——纯函数、无 LLM、可单测，所以它又快又稳。


## 内置技能

AIH 自带以下实用技能，开箱即用：

- **app-tour** — AIH 应用功能导览
- **batch-ops** — 批量操作指南
- **code-review** — 代码审查流程
- **find-skills** — 从社区生态中查找和安装技能
- **loop-design-check** — 循环设计检查
- **tui-design** — TUI 界面设计指南
- **web-design-guidelines** — Web 设计规范
- **session-report** — 会话报告生成

每个内置技能都可以通过 `load_skill("技能名")` 直接加载使用。

## 未来方向

技能系统的演进方向包括 **skill-creator**（技能创建器）和**自进化技能**（self-evolving skills）——即 AI 根据使用模式自动优化和生成新技能。这目前属于路线图规划中的功能，体现了技能系统向更低门槛、更智能化发展的趋势。
