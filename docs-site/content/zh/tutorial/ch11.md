# 第11章 事件流与调度

AIH 的运行时建立在一条不可变的事件流之上。每一轮对话、每一次工具调用都作为事件被忠实记录，构成了整个系统的单一事实来源。

## 追加日志：单一事实来源

AIH 的事件流采用 **追加式（append-only）** 设计。所有 `SessionEvent` 按严格序列号排序，支持完整重放。核心原则是：**模型可见的 = 可重放的**——任何影响模型决策的信息都必须经过事件流。

每个 `turn/end` 事件会累积 token 使用量（`cost.ts`），用于精确追踪会话成本。重放机制不仅是调试工具，也是状态恢复和会话分叉的基础。

## 观察者接口

**LoopObserver**（`core/src/observers.ts`）是 AIH 的核心扩展点，提供以下生命周期钩子：

- `onTurnStart` / `onTurnEnd`：轮次开始与结束
- `onModelResponse`：模型返回响应
- `onToolCall` / `onToolResult`：工具调用前后
- `onCompaction`：上下文压缩事件

**LoopAbort** 信号可以中断当前轮次——用于超时保护或外部干预。通过 **ToolHooks**（`before`/`after`）还可以注入审计和扩展逻辑，hooks 在瀑布模型中最后执行，确保不干扰核心流程。

## 确定性工作流

AIH 支持两种确定性调度机制：

**工作流**（`.aih/workflows/*.mjs`，`cli/src/workflow.ts`）是预定义的步骤序列，使用 Node.js 模块编写，可复现、可审计、可版本控制。

**任务**（`cli/src/jobs.ts`）是后台执行单元，与 headless 模式配合使用（`cli/src/serve.ts`）。工作流和任务共享同一事件流，确保可追溯性。

## 目标判定器

`/goal` 是 AIH 防止"乐观停止"的关键机制。每轮评估时，目标判定器作为独立 LLM 进行裁决，返回三态结果：

- `met`：目标已达成
- `unmet`：目标未达成
- `reason`：判定理由

独立判定器的设计避免了执行者自我评估的偏差——AI 不能自己宣布"任务完成"，必须由独立视角验证。这在长周期任务中尤为重要。

## 小结

事件流是 AIH 可靠性的基石。追加式日志保证可审计性，观察者接口提供扩展性，确定性工作流保证可复现性，目标判定器保证准确性。这四个支柱共同构成了一个值得信赖的 AI 执行框架。更多事件相关的状态管理可参考 [第 10 章](ch10)。
