# 第11章 事件流与调度

AIH 的运行时建立在一条不可变的事件流之上。每一轮对话、每一次工具调用都作为事件被忠实记录，构成了整个系统的单一事实来源。

> **先给小白的一句话**：把 AIH 的运行看成**一部不断录制的摄像机**——你说了什么、AI 回了什么、工具干了什么，全部录进一盘"只读的磁带"（append-only 事件流）。旁边还有一个**监制（观察者）**，随时报告"现在拍到哪一幕了"，但他只旁观、不改剧本。最后还有一个**验收员（/goal 裁判）**，独立判断"这部片子有没有拍完"。

## 追加日志：单一事实来源

AIH 的事件流采用 **追加式（append-only）** 设计。所有 `SessionEvent` 按严格序列号（`seq`）排序，支持完整重放。每个 `turn` 会被拆成一组有序事件，例如：

```
turn/start → user/message → assistant/message → tool/call → tool/result → goal/judge → turn/end
```

核心原则是：**模型可见的 = 可重放的**——任何影响模型决策的信息都必须经过事件流，没有"看不见的隐藏状态"。`turn/end` 事件会累积 token 使用量（`cost.ts`），用于精确追踪会话成本。重放机制不仅是调试工具，也是状态恢复和会话分叉的基础。

## 观察者接口

**LoopObserver**（`core/src/observers.ts`）是 AIH 的核心扩展点，提供以下生命周期钩子：

```ts
interface LoopObserver {
  onTurnStart?(turnId: string): void;                      // 一轮开始
  onTurnEnd?(turnId: string, stopReason: string): void;    // 一轮结束（含原因）
  onModelResponse?(turnId, text, toolCalls): void;         // 模型产出
  onToolCall?(turnId, call): void;                         // 工具被调用前
  onToolResult?(turnId, result): void;                     // 工具返回后
  onCompaction?(turnId, summaryChars): void;               // 上下文压缩时
}
```

这些钩子**只旁观、不改变主流程**——它们常被用来做 UI 更新、进度条、审计、指标采集。**LoopAbort** 信号可以中断当前轮次（超时保护或外部干预）。通过 **ToolHooks**（`before`/`after`）还可以注入审计和扩展逻辑，hooks 在瀑布模型中最后执行，确保不干扰核心流程。

## 确定性工作流

AIH 支持两种确定性调度机制：

- **工作流**（`.aih/workflows/*.mjs`，`cli/src/workflow.ts`）：预定义的步骤序列，用 Node.js 模块编写，可复现、可审计、可版本控制。每个工作流由若干 `WorkflowPhase` 组成，通过 `SendFn(prompt)` 逐阶段推进。
- **任务**（`cli/src/jobs.ts`）：后台执行单元，与 headless 模式配合使用（`cli/src/serve.ts`）。

工作流和任务共享同一事件流，确保可追溯性。

## 目标判定器

`/goal` 是 AIH 防"乐观停止"的关键机制。作者（执行者）很想说自己"做完了"；`/goal` 则请来一位**独立的验收员**——目标判定器作为独立 LLM 进行裁决，**agent 的自述不算证据**，只依据对话里真实可见的"证据"（工具结果、命令退出码、测试输出）。它返回三态结果：

```json
{ "met": true|false, "reason": "…", "unmet": ["…"] }
```

- `met`：目标已达成（`reason` 说明据什么验证的）
- `unmet`：目标未达成（`unmet` 列出还差哪几条标准，驱动自动续跑）
- `reason`：判定理由

独立判定器的设计避免了执行者自我评估的偏差——**AI 不能自己宣布"任务完成"，必须由独立视角验证**。这在长周期任务中尤为重要。判定结果本身也是一条 `goal/judge` 事件，同样可回放审计。

## 小结

事件流是 AIH 可靠性的基石。追加式日志保证可审计性，观察者接口提供扩展性，确定性工作流保证可复现性，目标判定器保证准确性。这四个支柱共同构成了一个值得信赖的 AI 执行框架。更多事件相关的状态管理可参考 [第 10 章](ch10)。
