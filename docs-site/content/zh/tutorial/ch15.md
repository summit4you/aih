# 社区与可复用技能

> **先给小白的一句话**：如果说技能是"借书"，那社区技能就是**从外馆调书**——通过 `find-skills` 里的 `searchRemote` 去远程"书库索引"（registry 的 `index.json`）查书，再用 `installRemoteSkill` 把整本书**原子地搬进本地书架**（`.aih/skills/`）。"原子"是关键：要么整本书一次到位，要么一本都不留，绝不给书架留一本**缺页的破书**。

AIH 的技能不仅可以自用，还可以通过社区生态共享和复用。本章介绍如何发现、安装和分享可复用技能，以及技能设计背后的核心原则。

## find-skills：技能发现入口

内置技能 **find-skills** 是进入社区生态的第一步。调用 `load_skill("find-skills")` 后，AI 助手会获得从开放 agent-skills 生态中查找和安装技能的能力。

你可以通过两种方式获取社区技能：

- **生态系统注册表**：搜索官方技能注册表中的已发布技能
- **GitHub URL**：直接指定 `owner/repo` 格式的 GitHub 仓库地址

安装过程将技能文件下载并放置到项目的 `.aih/skills/` 目录中，立即可用。

## 远程技能注册表

远程技能注册的底层实现在 `cli/src/skills.ts` 中，提供了一套完整的技能生命周期管理：

- **`fetchRegistryIndex`** — 拉取技能注册表索引，获取所有可用技能的元信息
- **`searchRemote`** — 按关键词搜索远程技能，支持版本过滤
- **`installRemoteSkill`** — 安装指定的远程技能，**版本感知且原子化**：安装要么完全成功，要么完全回滚，不会留下半成品

注册表 URL 的确定优先级为：**命令行标志 > `AIH_SKILL_REGISTRY` 环境变量 > `aih.json` 配置文件**。这让团队可以在不同环境中灵活配置技能来源。

### 从源码看"原子安装"

`installRemoteSkill`（`cli/src/skills.ts`）之所以"要么全有、要么全无"，核心是 **staging + rename 两段式**——先在一个临时目录把**所有**文件下载齐，再一次性 `rename` 进目标目录，失败则回滚备份：

```ts
const staging = `${destDir}.tmp-${token}`;        // 先下到"装货区"（staging）
try {
  for (const file of skill.files) {
    const url = new URL(file, `${skill.base}${skill.name}/`).href;
    writeFileSync(join(staging, file), await fetchText(url, timeoutMs));
  }
  if (!existsSync(join(staging, "SKILL.md")))      // 缺 SKILL.md = 整包报废
    throw new Error(`registry skill "${skill.name}" is missing SKILL.md`);
  // 版本感知：已装同版本 → no-op 直接返回，不重下
  if (version !== undefined && current === version && existsSync(skillMd)) return skillMd;

  if (existsSync(destDir)) {
    const backup = `${destDir}.old-${token}`;       // 旧目录先改名成备份
    renameSync(destDir, backup);
    try { renameSync(staging, destDir); }           // 装货区原子上位
    catch (err) { renameSync(backup, destDir); throw err; } // 失败 → 还原旧版
    rmSync(backup, { recursive: true, force: true });
  } else {
    renameSync(staging, destDir);
  }
} finally {
  rmSync(staging, { recursive: true, force: true }); // 无论成败，清空残留装货区
}
```

读这段的三个要点：

1. **staging 到位才算数**：所有文件（含 `SKILL.md`）先下载到临时目录，任何一步失败都不会污染真正的 `destDir`。
2. **版本感知的 no-op**：本地已有同版本技能则直接返回，避免无谓重下。
3. **rename 是原子的**：目录改名在同一文件系统内是不可分割的操作——要么新目录完全可见，要么回滚到旧备份，用户永远不会看到一个"装了一半"的技能。


## CLI 命令

AIH 提供了一组专门的技能管理命令：

```bash
aih skills list     # 列出已安装的技能
aih skills find     # 搜索可用技能
aih skills install  # 安装指定技能
aih skills show     # 查看技能详情
```

这些命令提供了命令行界面下完整的技能管理能力，适合自动化脚本和 CI/CD 集成。

## 设计原则：何时做技能

技能生态的设计遵循一个核心判断原则（OC#2）：

> 如果一个模式在 **2 个以上不同场景** 中反复出现，应该将其抽取为核心功能或 SDK。如果仅在**特定领域或一次性场景** 中使用，则做成技能或扩展，而不是给每次调用都增加核心负担。

技能本质上就是 **Markdown + 加载器**，创建和分享的成本极低，版本管理也很简单。这使得技能成为探索新场景、沉淀领域知识的理想载体。

## 分享与版本管理

当你的技能在团队内或社区中验证有效后，可以将其提交到生态系统注册表。由于技能只是 Markdown 文件，版本管理非常轻量——每次更新只需发布新版本的 `SKILL.md`，安装端会自动处理版本感知的升级。
