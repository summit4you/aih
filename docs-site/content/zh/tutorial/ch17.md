# 第17章 动手实践：端到端接入一个应用

本章以 AIH 内置的 Todo 应用为范例，从适配器编写到质量验证，完整走通端到端接入流程。请先阅读 [适配器规范](../adapter) 了解接入契约，再回到本章动手。

## 17.1 TodoAppAdapter 的真实接口

AIH 的核心抽象是 `AppAdapter`，定义在 `mcp-server/src/app-adapter.ts`。每个适配器暴露 `descriptor`（元数据）和 `context(query)` / `actions` 两个挂载面：

```ts
// 适配器必须实现的接口
interface AppAdapter {
  readonly descriptor: {
    name: string;
    version: string;
    description: string;
    contextQueries: string[];
    actions: Record<string, AppActionDef>;
  };
  context(query: string): Promise<unknown>;
  actions: Record<string, AppActionDef>;
}

// 每个 action 的结构
interface AppActionDef {
  description: string;
  kind: "read" | "write";
  permission: "allow" | "ask" | "deny";
  parameters: ZodSchema;        // 使用 zod 校验入参
  run: (args: Record<string, unknown>) => Promise<unknown>;
}
```

Todo 应用注册了四个 action：`list_todos`（read/allow）、`add_todo`（write/allow）、`toggle_todo`（write/ask）、`remove_todo`（write/ask），以及 `all`、`open`、`done`、`stats` 四个 context query。

## 17.2 编写一个自定义 action

下面示范在 TodoAppAdapter 基础上新增一个查询已完成任务数量的只读 action：

```ts
import { z } from "zod";

const countDoneAction = {
  description: "统计已完成待办数量",
  kind: "read" as const,
  permission: "allow" as const,
  parameters: z.object({}),
  run: async () => {
    const todos = await context("done");
    return { count: todos.length };
  },
};
```

关键要点：`kind:"read"` + `permission:"allow"` 意味着模型可以不经确认直接调用；`kind:"write"` 的 action 默认会要求用户确认（`ask`）。参数 schema 使用 zod 对象，方便模型生成合法输入。

## 17.3 CLI 挂载与运行

AIH CLI 将适配器的 action 逐个挂载为顶层工具命令：`list_todos`、`add_todo`、`toggle_todo`、`remove_todo`。写操作（write）在 TTY 模式下弹出 `[y/N]` 确认，非 TTY 模式需显式传入 `--yes` 跳过确认。

启动方式有三种：
- **交互式 TUI**：直接运行 `aih`，进入交互终端。
- **离线模式**：`aih run "<prompt>" --mock`，无需真实模型。
- **真实模型**：配置 `AIH_BASE_URL` / `AIH_MODEL` / `AIH_API_KEY` 后运行 `aih run "<prompt>"`。

## 17.4 通过 @aih/core 嵌入

在自有进程里嵌入 AIH 时，使用 `@aih/core` 的 `ToolRegistry` 和 `AgentLoop`：

```ts
import { ToolRegistry, AgentLoop } from "@aih/core";

const registry = new ToolRegistry();
registry.register({
  name: "list_todos",
  description: "列出所有待办",
  kind: "read",
  permission: "allow",
  run: async () => { /* ... */ },
});

const loop = new AgentLoop({ tools: registry, /* model config */ });
await loop.run("列出所有未完成的任务");
```

这正是 [第 16 章](ch16) 中所说的"通用内核 + 注入应用工具"的体现。

## 17.5 质量门禁：honesty gate

接入完成后，必须通过三项质量检查：

| 命令 | 作用 | 说明 |
|---|---|---|
| `npm test` | smoke 测试 | 覆盖 core / mcp / cli 三个模块 |
| `npm run check` | 构建 + 契约一致性 | 确认代码与 adapter 契约同步 |
| `npm run eval` | 完整门禁 | doctor + bootstrap + check + test 四步 |

`npm run eval` 是最终的交付门禁（hand-off gate），全部通过才说明接入合格。更多测试策略请参考 [第 16 章](ch16) 中的持续集成实践。
