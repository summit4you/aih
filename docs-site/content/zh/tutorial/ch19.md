# 第19章 案例：HemaGuide 血液肿瘤决策支持

前面各章拆解的是 AIH 自身。本章换一个视角：一个**领域应用**——血液肿瘤学的临床决策支持
系统 HemaGuide——如何**不改动 AIH 一行核心代码**，只靠现有原语（extension / workflow /
skill / 共享 lib）就骑上来。它是"通用内核 + 注入领域逻辑"（[第 18 章](ch18)）最完整的实例。

> **先给小白的一句话**：血液肿瘤科医生面对一个复发病例或一份 NGS 报告时，要做的是
> 把指南、既往病例、分子证据拼起来给出一个"会议式决议"。HemaGuide 让 LLM 干它擅长的
> 抽取、路由、综合，而把**数值评分**这种绝不能自由发挥的部分交给代码。

> **安全边界（贯穿全章）**：本章所有病例与分子证据都是**合成、去标识化**的替身数据，
> 实现与文档均标注 **RESEARCH USE ONLY**——不用于患者诊疗或真实临床运行。任何"决议"
> 必须由合格医学专业人员独立核验后方可参考。

## 19.1 背景：论文想解决什么

HemaGuide（*Clinical Decision Support in Hematological Malignancies Using a Case-Grounded
AI Agent*）针对血液恶性肿瘤（AML、DLBCL、多发性骨髓瘤等）的决策支持，核心论点是：

**数值/结构化推理不能交给自由发挥的 LLM。** 变异评分、阈值判定、互斥规则必须落到可审计
的代码里；LLM 只负责它擅长的抽取、路由、综合。

论文把决策拆成三个模式：

| 模式 | 何时用 | 证据源 |
|---|---|---|
| **GUIDELINE** | 病例走疾病流程图（初诊、标准方案） | 指南流程图数据 |
| **ADVANCED** | 病例超出指南（罕见标志物、既往失败、需要先例） | 既往病例库（向量检索） |
| **MOLECULAR** | 分子肿瘤板 / NGS 变异解读 | 分子证据 + **确定性评分模型** |

MOLECULAR 模式背后是一个 12 准则的致癌性评分模型（Horak et al. 2022 / ClinGen-CGC-VICC
传统）：人群频率、热点、变异类型、结构域、功能证据、计算预测六个维度，正负分相加，
按阈值映射到五级分类——`Oncogenic ≥10` · `Likely Oncogenic 6–9` · `VUS 0–5` ·
`Likely Benign −6~−1` · `Benign ≤−7`，并带互斥规则（例如已命中强致癌证据 OS3 时，
弱证据 OM1 不再叠加）。

## 19.2 论文 → AIH 原语的映射

本仓库的复现（`examples/hemaguide/`）把论文的每个部件映射到 AIH 原语，**没有改 core**：

| HemaGuide（reference） | 本实现（AIH 原语） | 为什么 |
|---|---|---|
| `src/mol/*` 8 个证据层 → 评分工具 | **`lib/scorer.mjs`**（确定性 12 准则评分） | 论文的安全底线：评分是**代码**，不是 LLM。纯函数、离线可测、可被断言。 |
| `src/vectordb.py`（向量数据库检索既往病例） | **`lib/retriever.mjs`**（BM25 检索，CJK/latin 感知） | 同一设计意图（检索相似病例、按实体过滤、按片段重叠排序），但**零外部服务**，普通硬件离线可跑。 |
| `src/decision.py` 三决策模式 | **extension 三个工具** + **workflow 路由阶段** | LLM 路由到模式（论文留给模型的部分），代码执行模式（论文坚持不能自由发挥的部分）。 |
| `data/onkopedia.json`（指南流程图） | **`data/flowcharts.json`** | GUIDELINE 模式的证据源。 |
| 基因分类表 + 8 个上游 API | **`data/molecular-evidence.json`**（本地策展表） | 替身 gnomAD / cancerhotspots / CIViC / OncoKB 等 8 个上游 API，让评分离线可跑。 |
| `src/extraction.py`（病例 8 节抽取） | **workflow `extract` 阶段** | LLM 把自由文本病例结构化成 8 节（age/ECOG/diagnosis/…/molecular）。 |
| 整条管线（抽取→路由→证据→综合） | **`.aih/workflows/hemaguide.mjs`**（4 阶段，每阶段 `expect` 子串门） | 机器可判定、fail-fast：错误/缺失的答案不会继续往下传。 |

## 19.3 确定性评分核心

`lib/scorer.mjs` 是论文 `src/mol/*` 的忠实 JS 复现。12 准则的分值表：

| 维度 | 准则 | 分值 |
|---|---|---|
| 人群频率 | SBVS1（MAF>5%）/ SBS1（MAF>1%） | −8 / −4 |
| 人群频率 | OP4（MAF<0.01% 或缺失） | +1 |
| 热点 | OS3 / OM3 / OP3 | +4 / +2 / +1 |
| 变异类型 | OVS1（抑癌基因 null 变异）/ OM2（癌基因框内 indel） | +8 / +2 |
| 结构域 | OM1（关键功能域） | +2 |
| 功能证据 | OS2（体外/体内功能研究） | +4 |
| 计算预测 | OP1 / SBP1 | +1 / −1 |

互斥规则保证同一维度不重复计分（例如 OS3 命中后 OM1 不再叠加）。输入是变体列表，
输出是**逐准则的命中明细 + 总分 + 五级分类**——因为每一步都是纯函数，所以可以
`assert`：`TP53 p.Arg273His → 10 分 → Oncogenic`、`NPM1 突变（无 OVS1）→ 7 分 →
Likely Oncogenic` 这类断言都写进了验证脚本。

## 19.4 三种用法：CLI / 交互工具 / 确定性管线

同一个 `lib/`，三个入口——这正是"重复需求 → seam"（[第 18 章](ch18)）的落点：

```bash
# ① 直接 CLI：确定性核心，无 LLM，离线可跑
node examples/hemaguide/bin/hemaguide.mjs score '{"variants":[{"gene":"TP53","aa_change":"p.Arg273His"}]}'
node examples/hemaguide/bin/hemaguide.mjs retrieve --query "relapsed AML TP53" --entity AML
node examples/hemaguide/bin/hemaguide.mjs flowchart --entity AML
```

```text
# ② 交互式：extension 把三个模式注册成工具（aih run / chat / tui 自动加载）
> hemaguide_score { "variants": [...] }
> hemaguide_retrieve { "query": "relapsed AML TP53 complex karyotype" }
> hemaguide_flowchart { "entity": "AML" }
```

```bash
# ③ 确定性管线：4 阶段 workflow，本地模型即可端到端跑通
AIH_BASE_URL=<你的 OpenAI 兼容端点> AIH_MODEL=<模型> AIH_API_KEY=<key> \
node cli/dist/index.js workflow run hemaguide --dev --yes
```

> **关键架构约束**：`aih workflow run` 路径**不加载 extensions**，但暴露 `run_cmd`。
> 所以 workflow 的确定性证据步骤走**共享 CLI**（`bin/hemaguide.mjs`）经 `run_cmd` 调用——
> 与 extension 和直接 CLI 用的是**同一份 `lib/` 代码**，不复制粘贴；交互式工具走
> extension（`aih run`/`chat` 才加载 extensions）。

## 19.5 PHI 安全门：把"问人"做成代码

extension 在 `tool:before` 钩子上装了一道 PHI（受保护健康信息）门：凡是 `hemaguide_*`
工具调用的参数里出现**直接患者标识**（SSN / patient-id / DOB / email 等），直接拦截、
要求先去标识化。它不是提示词层面的"请注意"，而是调用发生前就取消的硬门——与
[第 13 章](ch13)讲的"安全层永远先于扩展"同构，只是这里安全层由领域方自己定义。

## 19.7 本章要点

- **领域逻辑不进 core**：HemaGuide 的全部评分/检索/数据都在 `examples/` 与
  `.aih/extensions|workflows`，AIH core 零改动——这就是"通用内核 + 注入应用工具"。
- **数值推理归代码，编排归 LLM**：评分是纯函数（可断言、离线可复现），LLM 只做
  抽取/路由/综合，且综合结果必须引用确定性分类与点数。
- **一个 `lib/`，三个入口**：CLI、extension 工具、workflow 经 `run_cmd` 复用同一份代码。
- **安全是显式的**：RESEARCH USE ONLY 贯穿数据与文档；PHI 门是调用前取消的硬门，
  不是提示词约定。
