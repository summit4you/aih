# The Session System

A session in AIH is the complete record of an agent's interactions with the model. Understanding the session system is the first step to mastering AIH workflows.

> **Plain words for newcomers**: think of the session log as a **ledger that only ever grows and is never altered**. Every event—what you said, what the model replied, what a tool did—is **appended** to the end. Want to go back to an earlier moment? You don't tear out the later pages; you **open a fresh branch from that page** and keep recording there. Because of this, any record can be recovered, replayed, and audited.

## SessionLog: Append-Only Event Stream

`SessionLog` (`core/src/session-log.ts`) uses an **append-only JSONL** format—every event can only be appended, never modified in place.

What does "append-only" really mean? Here is the core interface (simplified but faithful to the source):

```ts
class SessionLog {
  append(event): SessionEvent        // append one event, returns the recorded fact
  fork(fromSeq = 0): SessionLog      // "fork" a new log from a historical sequence
  checkpoint(name): SessionEvent     // drop a named save-point (itself an event)
  restoreTo(checkpointSeq): SessionLog  // "rollback" = keep only the prefix up to the point
}
```

The key nuance: **rollback is not deletion**. `restoreTo(checkpointSeq)` finds the nearest `type === "checkpoint"` event with `seq <= checkpointSeq`, then keeps `filter(e => e.seq <= checkpointSeq)` — it **keeps the prefix rather than erasing history**. So:

- **Model-visible content = replayable event sequence**: anything that influences the model's decisions must first become an event. There is no "invisible hidden state."
- **Rollback = prefix fork**: create a new event branch from a historical position; the original branch stays untouched.
- **Crash-recoverable**: once events hit disk they are persisted, so an unexpected process exit loses nothing already written.

## Checkpoints: Saving State

An editor's **Ctrl+Z undo** only steps back once; AIH checkpoints are **named save-points**: drop a `checkpoint(name)` at any moment, and `restoreTo` whenever you like. Because a checkpoint is itself an append-only event, "saving" is equally replayable and auditable. Combined with the session commands in `cli/src/sessions.ts` (`fork`, `checkpoint`, `restore`), you can treat a failed attempt as if it never happened and re-plan from the save-point.

## Compaction and Context Management

As a conversation grows, the context window fills up. AIH provides three compaction strategies:

- **Active compaction**: runs automatically before the first step of each turn, keeping model input within the context limit.
- **Passive compaction**: triggers automatically when context exceeds the `compactAt` threshold.
- **Manual compaction**: triggered explicitly by the user via a command.

Each compaction projection is verified through **`coverageDigest`** — a **SHA-256 hash** (32 hex characters) over the prefix of events it claims to cover (`upToSeq`). On replay, the hash is recomputed; **if it doesn't match, that compaction is treated as if it never happened** (in the source: `continue`). This guarantees the projection exactly matches the log it claims to cover — the model never sees a history "that doesn't add up" because of compaction.

```ts
// Replay-time verification (simplified): digest mismatch → pretend it never happened
if (coverageDigest(events.filter(e => e.seq <= event.coverage.upToSeq))
      !== event.coverage.digest) {
  continue; // treat as if this compaction never happened
}
```

## Tool Output Caps

To prevent a single tool call from consuming too much context, AIH enforces two layers of limits:

- **Per-result cap** `TOOL_OUTPUT_MAX_CHARS = 8192`: maximum characters for a single tool output.
- **Per-turn budget** `TURN_TOOL_BUDGET_CHARS = 512000`: aggregate character budget for all tool outputs in a single turn. When exceeded, the earliest results are kept intact and later outputs are truncated. A `TURN_BUDGET_STOP_DIRECTIVE` is injected to notify the model.

## Persistence and Session Management

`session-store.ts` uses **temp-file + atomic rename** (`#publish`) for safe writes — the content is first written to a temp file, then renamed into place in a single step, avoiding a half-written file on a crash mid-write. A metadata sidecar and torn-tail repair ensure data integrity.

Session management commands (`cli/src/sessions.ts`) support save, fork, tree view, checkpoint, restore, and resume. In the CLI, use `--session <name>` to specify a session and `-c` to resume the most recent one. CJK token estimation is roughly 1 character per token, while other languages average about 1 token per 3.5 characters.
