# The Agent System

> **Plain words for newcomers**: `AgentLoop` is like a **very patient telephone operator** — it dials the model's "phone" (`LLM.complete`) again and again, and within a single call it may let the assistant make several "internal transfers" (tool-call steps). When the call fails or stalls, it retries a **bounded number of times**: no answer (empty response) 2 tries, a garbled call (stream stall) 1 resume, "please call back later" (quota 429) up to 2 waits — **every retry has a ceiling**, so a bad conversation can never loop forever.

The agent is AIH's core execution unit. `AgentLoop` drives the complete cycle of model requests, tool calls, and error retries.

## AgentLoop: Turn/Step Execution Cycle

`AgentLoop` (`core/src/agent-loop.ts`) uses a two-level **turn/step** loop:

- **Turn**: a complete model response (which may include multiple tool calls).
- **Step**: a single tool execution within a turn.

The loop has built-in multi-layer fault tolerance:

- `MAX_EMPTY_RETRIES = 2`: max retries when the model returns an empty response.
- `MAX_STALL_RESUMES = 1`: max resumes after a stream stall.
- `MAX_QUOTA_WAITS = 2`: max wait-and-retry attempts on quota exhaustion (429).

Additional mechanisms include **stream-stall resume** and **quota 429 wait-then-reissue**.

## Reading the Fault Tolerance: Three "Call-Failed" Fallbacks

These retry **numbers** aren't arbitrary — they're explicit constants in `core/src/agent-loop.ts`, and **each has an upper bound**:

```ts
/** Max consecutive empty responses (no text + no tool call) we nudge the model to retry. */
const MAX_EMPTY_RETRIES = 2;
/** CC#49 — max stream-stall resumes per turn (a flaky provider can't loop forever). */
const MAX_STALL_RESUMES = 1;
/** CC#51 — quota-exhaustion (429) auto-resume cap. */
const MAX_QUOTA_WAITS = 2;
```

The actual fallback logic lives in the turn's step loop (`while (steps < this.#maxSteps ...)`), in layered `try/catch`:

```ts
try {
  response = await doComplete();          // dial the "model phone"
} catch (err) {
  if (ac.signal.aborted) break;           // user cancelled → let go
  if (err instanceof StallError && stallResumes < MAX_STALL_RESUMES) {
    stallResumes += 1;                    // stream stalled but partial text already emitted
    this.#log.append({ type: "assistant/message", turnId, text: partial }); // keep what we got
    continue;                             // append "please finish your thought", continue next round
  }
  if (err instanceof QuotaError && hooks?.quotaWait && quotaWaits < MAX_QUOTA_WAITS) {
    quotaWaits += 1;                      // quota exhausted: wait for reset then reissue
    await sleepMs(waitSec * 1000, ac.signal); // source comment: re-issue the SAME rejected call
    continue;                             // not re-run the whole turn
  }
}
```

Three design takeaways:

1. **Bounded retries**: all `MAX_*_WAITS/RETRIES` are tiny integers, structurally preventing a bad conversation from looping forever and burning tokens (the key to loop anti-runaway).
2. **Preserve partial progress**: on a stream stall, the already-emitted `partialText` is written to the log *before* asking the model to "finish", rather than restarting from scratch.
3. **Reissue, don't replay**: on quota exhaustion, the LLM *reissues the same rejected call* (the source comment explicitly says *not re-run the turn*), avoiding side effects from duplicate tool execution.

## Build / Plan Dual Mode

AgentLoop supports two operating modes:

- **Build mode**: all tools are available, including write operations.
- **Plan mode**: write tools are hidden, allowing only read-only operations—ideal for the planning phase.

Switch between modes with the Tab key or the `/mode build` command.

## Seams (Extension Points)

AgentLoop offers rich extension points for customization:

- **systemPrompt**: customize the system prompt.
- **observers** (`LoopObserver`): listen to `onTurnStart`, `onTurnEnd`, `onModelResponse`, `onToolCall`, `onToolResult`, `onCompaction` events. `LoopAbort` can interrupt the current turn.
- **onPromptInput**: debug hook for input interception.
- **compactContext**: custom compaction strategy.
- **budget/costOf**: custom budget and cost calculation.
- **sensors**: runtime sensors.
- **onEscalate**: escalation handling hook.

## Sub-Agents

AIH supports several sub-agent patterns:

- **task**: serial execution with its own context, ideal for decomposing subtasks.
- **best_of_n**: runs N candidates in parallel + a judge picks the best result, suitable for high-stakes decisions (see [Ch.7](ch07) for model adaptation details).
- **teams**: multi-agent collaborative teams.
