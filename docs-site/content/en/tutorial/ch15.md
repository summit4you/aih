# Community & Reusable Skills

> **Plain words for newcomers**: if skills are "borrowing books", then community skills are **inter-library loans** — via `searchRemote` inside `find-skills` you look up a remote "library index" (the registry's `index.json`), then `installRemoteSkill` **atomically moves the whole book onto your local shelf** (`.aih/skills/`). "Atomic" is the key: either the entire book arrives at once, or none of it — the shelf is never left with a **torn, page-missing book**.

AIH skills aren't just for personal use—they can be shared and reused through the community ecosystem. This chapter covers how to discover, install, and share reusable skills, plus the core design principles behind them.

## find-skills: The Discovery Entry Point

The built-in **find-skills** skill is your gateway to the community ecosystem. After loading it with `load_skill("find-skills")`, the AI assistant gains the ability to search and install skills from the open agent-skills ecosystem.

You can acquire community skills in two ways:

- **Ecosystem registry**: search the official skill registry for published skills
- **GitHub URL**: specify a GitHub repository directly in `owner/repo` format

Installation downloads the skill file and places it in your project's `.aih/skills/` directory, making it immediately available.

## Remote Skill Registry

The underlying remote skill registration system lives in `cli/src/skills.ts`, providing a complete skill lifecycle:

- **`fetchRegistryIndex`** — pulls the skill registry index, fetching metadata for all available skills
- **`searchRemote`** — searches remote skills by keyword with version filtering
- **`installRemoteSkill`** — installs a specified remote skill, **version-aware and atomic**: installation either fully succeeds or fully rolls back, leaving no partial state

Registry URL resolution follows this priority: **CLI flags > `AIH_SKILL_REGISTRY` env var > `aih.json` config file**. This lets teams flexibly configure skill sources across different environments.

### Reading the "Atomic Install" from Source

Why is `installRemoteSkill` (`cli/src/skills.ts`) "all or nothing"? The key is a **staging + rename two-phase** approach — first download **all** files into a temp directory, then `rename` into the destination in one step, rolling back to a backup on failure:

```ts
const staging = `${destDir}.tmp-${token}`;        // download into the "loading bay" (staging) first
try {
  for (const file of skill.files) {
    const url = new URL(file, `${skill.base}${skill.name}/`).href;
    writeFileSync(join(staging, file), await fetchText(url, timeoutMs));
  }
  if (!existsSync(join(staging, "SKILL.md")))      // missing SKILL.md = whole package scrapped
    throw new Error(`registry skill "${skill.name}" is missing SKILL.md`);
  // version-aware: same version already installed → no-op, don't re-download
  if (version !== undefined && current === version && existsSync(skillMd)) return skillMd;

  if (existsSync(destDir)) {
    const backup = `${destDir}.old-${token}`;       // rename old dir into a backup
    renameSync(destDir, backup);
    try { renameSync(staging, destDir); }           // loading bay atomically moves into place
    catch (err) { renameSync(backup, destDir); throw err; } // on failure, restore the old version
    rmSync(backup, { recursive: true, force: true });
  } else {
    renameSync(staging, destDir);
  }
} finally {
  rmSync(staging, { recursive: true, force: true }); // clean up leftovers whether it succeeded or not
}
```

Three takeaways:

1. **Nothing counts until staging is complete**: all files (including `SKILL.md`) are downloaded to a temp directory first; any failure never pollutes the real `destDir`.
2. **Version-aware no-op**: if the same version is already installed locally, return immediately instead of downloading again.
3. **rename is atomic**: a directory rename within the same filesystem is an indivisible operation — either the new directory is fully visible, or it rolls back to the old backup; the user never sees a "half-installed" skill.


## CLI Commands

AIH provides a dedicated set of skill management commands:

```bash
aih skills list     # list installed skills
aih skills find     # search available skills
aih skills install  # install a specified skill
aih skills show     # view skill details
```

These commands offer complete skill management from the command line, suitable for automation scripts and CI/CD integration.

## Design Principle: When to Make a Skill

The skill ecosystem follows a core design judgment (OC#2):

> If a pattern recurs across **2+ different contexts**, extract it into core/SDK. If it's **domain-specific or one-off**, make it a skill or extension—don't tax every call with core additions.

Skills are just **Markdown + loader**, making creation and sharing extremely cheap with simple versioning. This makes skills the ideal vehicle for exploring new scenarios and crystallizing domain knowledge.

## Sharing & Version Management

Once your skill is validated within a team or community, you can submit it to the ecosystem registry. Since skills are just Markdown files, version management is lightweight—each update simply publishes a new version of `SKILL.md`, and the installation side handles version-aware upgrades automatically.
