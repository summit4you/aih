# The Tool System

AIH's tool system is the bridge between the agent and the outside world. All tools are registered, looked up, and invoked through the `ToolRegistry`.

## ToolRegistry and ToolDefinition

`ToolRegistry` (`core/src/tool-registry.ts`) provides four core methods: `register`, `get`, `schemas`, and `invoke`. Each tool is a `ToolDefinition` object containing:

- **name**: tool identifier
- **description**: functional description (for the model)
- **parameters**: parameter schema
- **kind**: read/write classification
- **permission**: permission policy (static string or dynamic function)
- **execute**: the actual execution logic

Calling `schemas()` returns an array of `ToolSchema` objects used by the model to choose tools.

## The Guard Pipeline

Every tool invocation passes through five guard stages in `invoke()`:

1. **Permission resolution**: resolves `def.permission` (static string or function) to allow/deny. Denial returns a denied result immediately.
2. **Doom-loop detection**: when identical calls repeat—at `DOOM_LOOP_ASK_AT = 3` it asks the user for confirmation, at `DOOM_LOOP_DENY_AT = 6` it hard-denies.
3. **Before hooks**: perform redaction, timing, and audit; if `AskError` is raised, human confirmation is forced.
4. **Execute**: runs the tool's actual logic.
5. **After hooks**: result rewriting and audit logging.

## App Tools and Built-in General Tools

AIH tools come from two sources:

- **App tools**: provided by `AppAdapter` actions (see [Ch.8](ch08)).
- **Built-in general tools** (`cli/src/dev-tools.ts` + `general-tools.ts`): `list_dir`, `read_file`, `write_file`, `run_cmd`, `edit`, `glob`, `grep`, `webfetch`, `websearch`, `task`, `best_of_n`, `question`, `remember`, `load_skill`, `todo`.

When an app tool and a built-in tool share the same name, the **app tool wins**.

## Parallel Read-Only Execution

To improve efficiency, AIH supports parallel read-only calls (F#29): consecutive read-only tool invocations run concurrently, capped at `AIH_TOOL_CONCURRENCY` (default 4). Write operations always execute serially. All results are returned in the original call order, implemented via `mapConcurrent` in `agent-loop.ts`.
