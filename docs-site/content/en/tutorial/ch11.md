# Chapter 11: Event Stream and Scheduling

AIH's runtime is built on an immutable event stream. Every conversation turn, every tool invocation is faithfully recorded as an event, forming the single source of truth for the entire system.

## Append-Only Log: The Single Source of Truth

AIH's event stream uses an **append-only** design. All `SessionEvents` are ordered by strict sequence numbers and support full replay. The core principle is: **model-visible = replayable** — any information that influences model decisions must flow through the event stream.

Each `turn/end` event accumulates token usage (`cost.ts`) for precise session cost tracking. The replay mechanism is not only a debugging tool but also the foundation for state recovery and session forking.

## Observer Interfaces

**LoopObserver** (`core/src/observers.ts`) is AIH's primary extension point, providing these lifecycle hooks:

- `onTurnStart` / `onTurnEnd`: Turn beginning and completion
- `onModelResponse`: Model returns a response
- `onToolCall` / `onToolResult`: Before and after tool invocations
- `onCompaction`: Context compaction events

**LoopAbort** signals can interrupt a mid-turn execution — useful for timeout protection or external intervention. **ToolHooks** (`before`/`after`) allow injecting audit and extension logic; hooks execute last in the waterfall pattern, ensuring they never interfere with core flow.

## Deterministic Workflows

AIH supports two deterministic scheduling mechanisms:

**Workflows** (`.aih/workflows/*.mjs`, `cli/src/workflow.ts`) are predefined step sequences written as Node.js modules. They are reproducible, auditable, and version-controllable.

**Jobs** (`cli/src/jobs.ts`) are background execution units, designed for headless operation (`cli/src/serve.ts`). Both workflows and jobs share the same event stream, ensuring full traceability.

## Goal Judge

The `/goal` mechanism is AIH's key defense against "optimistic stopping." During each evaluation round, the goal judge acts as an independent LLM to render a verdict, returning a three-state result:

- `met`: Goal has been achieved
- `unmet`: Goal has not been achieved
- `reason`: Rationale for the verdict

The independent judge design prevents self-assessment bias — the AI cannot declare "task complete" on its own; an independent perspective must verify. This is especially critical for long-running tasks.

## Summary

The event stream is the foundation of AIH's reliability. Append-only logs guarantee auditability, observer interfaces provide extensibility, deterministic workflows ensure reproducibility, and the goal judge ensures accuracy. Together these four pillars form a trustworthy AI execution framework. For event-related state management, see [Ch.10](ch10).
