# Chapter 11: Event Stream and Scheduling

AIH's runtime is built on an immutable event stream. Every conversation turn, every tool invocation is faithfully recorded as an event, forming the single source of truth for the entire system.

> **Plain words for newcomers**: imagine AIH's runtime as an **always-recording camera** — what you say, what the AI replies, and what tools do are all recorded onto a **read-only tape** (the append-only event stream). Beside it sits a **director (the observer)** who reports "which scene we're on now," but only watches, never rewrites the script. Finally there's an **acceptance officer (the `/goal` judge)** who independently decides "is this film finished or not."

## Append-Only Log: The Single Source of Truth

AIH's event stream uses an **append-only** design. All `SessionEvent`s are ordered by strict sequence numbers (`seq`) and support full replay. Each `turn` is broken into an ordered sequence of events, for example:

```
turn/start → user/message → assistant/message → tool/call → tool/result → goal/judge → turn/end
```

The core principle is: **model-visible = replayable** — any information that influences model decisions must flow through the event stream; there is no "invisible hidden state." Each `turn/end` event accumulates token usage (`cost.ts`) for precise session cost tracking. The replay mechanism is not only a debugging tool but also the foundation for state recovery and session forking.

## Observer Interfaces

**LoopObserver** (`core/src/observers.ts`) is AIH's primary extension point, providing these lifecycle hooks:

```ts
interface LoopObserver {
  onTurnStart?(turnId: string): void;                      // a turn begins
  onTurnEnd?(turnId: string, stopReason: string): void;    // a turn ends (with reason)
  onModelResponse?(turnId, text, toolCalls): void;         // model produced output
  onToolCall?(turnId, call): void;                         // a tool is about to run
  onToolResult?(turnId, result): void;                     // a tool returned
  onCompaction?(turnId, summaryChars): void;               // context was compacted
}
```

These hooks **only observe, never change the main flow** — they're commonly used for UI updates, progress bars, audit, and metrics. **LoopAbort** signals can interrupt a mid-turn execution (timeout protection or external intervention). **ToolHooks** (`before`/`after`) allow injecting audit and extension logic; hooks execute last in the waterfall pattern, ensuring they never interfere with core flow.

## Deterministic Workflows

AIH supports two deterministic scheduling mechanisms:

- **Workflows** (`.aih/workflows/*.mjs`, `cli/src/workflow.ts`): predefined step sequences written as Node.js modules — reproducible, auditable, and version-controllable. Each workflow is composed of `WorkflowPhase`s, advanced phase by phase through `SendFn(prompt)`.
- **Jobs** (`cli/src/jobs.ts`): background execution units, designed for headless operation (`cli/src/serve.ts`).

Both workflows and jobs share the same event stream, ensuring full traceability.

## Goal Judge

The `/goal` mechanism is AIH's key defense against "optimistic stopping." The author (executor) very much wants to say "I'm done"; `/goal` calls in an **independent acceptance officer** — the goal judge, an independent LLM whose verdict **does not treat the agent's own claim as evidence**, relying only on the evidence actually visible in the conversation (tool results, command exit codes, test output). It returns a three-state verdict:

```json
{ "met": true|false, "reason": "…", "unmet": ["…"] }
```

- `met`: Goal achieved (`reason` says what verified it)
- `unmet`: Goal not achieved (`unmet` lists which criteria remain, driving auto-continue)
- `reason`: Rationale for the verdict

The independent judge design prevents self-assessment bias — **the AI cannot declare "task complete" on its own; an independent perspective must verify**. This is especially critical for long-running tasks. The verdict itself is recorded as a `goal/judge` event, equally replayable and auditable.

## Summary

The event stream is the foundation of AIH's reliability. Append-only logs guarantee auditability, observer interfaces provide extensibility, deterministic workflows ensure reproducibility, and the goal judge ensures accuracy. Together these four pillars form a trustworthy AI execution framework. For event-related state management, see [Ch.10](ch10).
