# Chapter 12: CLI and TUI

AIH provides a full-featured command-line interface (CLI) and terminal user interface (TUI), covering everything from interactive chat to headless services. This chapter covers the command surface, TUI interactions, and mode switching.

## Command Surface

AIH's command entry point lives in `cli/src/index.ts`, where the `main` function dispatches to subcommands:

- **aih / aih chat**: Launch the interactive TUI session
- **aih run**: Non-interactive execution
- **aih tools**: List available tools
- **aih describe**: View tool details
- **aih config**: Manage configuration
- **aih session**: Session management (`list`, `show`, `export`, `fork`, `checkpoint`, `restore`)
- **aih skills**: Skill management (`list`, `find`, `install`, `show`)
- **aih stats**: View usage statistics
- **aih serve** / **aih attach**: Headless service and connection
- **aih coverage** / **aih quality**: Coverage and quality reports
- **doctor --fix**: Auto-repair common issues

The bare `aih` command requires a TTY to start an interactive session; otherwise it prints help text.

## TUI Interface

The TUI implementation lives in `cli/src/tui.ts` with an opencode-style design. Keybinds are defined in `cli/src/keybinds.ts` and `tui.json`.

Core interactive elements include:

- **Tab / `/mode build`**: Switch between build and plan modes
- **`/usage`**: View token consumption
- **`/goal`**: Set or inspect the current goal
- **Context panel**: Displays cost (`$x`), token rate (`N tok/s`)
- **Status bar**: Shows current mode and connection state

Markdown tables render natively in the TUI. CJK characters and emoji are measured with `string-width` for correct alignment.

## Dev Mode Semantics

The `--dev` and `--no-dev` flags control the available toolset scope:

- **aih chat**: Local toolset enabled by default (`--no-dev` disables it)
- **aih run / aih workflow / aih tools**: Local toolset disabled by default, requires explicit `--dev`

This design ensures production environments never accidentally expose development tools. Interactive sessions are more permissive; automated executions are stricter — following the principle of least surprise.

## Non-TTY Dispatch

When `aih chat` runs in a non-TTY environment, it degrades to headless mode. `aih serve` starts an HTTP server, and `aih attach` connects to an existing instance. This enables AIH to embed in CI/CD pipelines, remote servers, and container environments.

## Summary

AIH's CLI and TUI embody "progressive complexity": simple commands work out of the box, advanced features unlock gradually through flags and subcommands. Whether you're a terminal newcomer or a power user, there's an interaction style that fits.
