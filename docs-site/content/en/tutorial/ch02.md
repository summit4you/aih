# Project Structure & Development Environment

## Monorepo Overview

AIH uses an npm workspaces monorepo. The root `package.json` declares three workspaces: `core`, `mcp-server`, and `cli`. Top-level layout:

```
aih/
├── core/            # L1 kernel (agent-loop / tool-registry / session-log / seams / prompts)
├── cli/             # CLI + TUI + local tools (dev-tools / general-tools / gate / config)
├── mcp-server/      # L0 adapter layer (app-adapter / todo-app example)
├── docs-site/       # Documentation site (standalone package, marked as only dependency)
├── scripts/         # doctor / check / eval / install / package scripts
├── evals/           # Evaluation test cases
├── examples/        # Example projects
├── skills/          # Built-in skills (SKILL.md)
├── tasks/           # Task briefs
├── docs/            # Internal design docs (roadmap / decisions / parity-matrix)
├── aih.json         # Runtime configuration
├── harness.yml      # Declarative harness config
├── APP.md           # App intelligence agent contract (single source of truth)
├── start.sh         # Local launch script (opencode Zen free-tier gateway)
└── package.json     # Root package (workspaces + scripts)
```

## Getting Started from Source

Prerequisites: **Node.js ≥ 20**. Clone and bootstrap:

```sh
git clone https://github.com/summit4you/aih && cd aih
npm run bootstrap   # Install all workspace dependencies
npm run doctor      # Environment readiness check
npm run check       # tsc build + contract consistency check
npm test            # Smoke tests: core → mcp-server → cli
npm run eval        # Full handoff gate (doctor + bootstrap + check + test chained)
```

Quick verification:

```sh
npm run cli -- run "add a todo buy milk" --mock   # --mock offline demo, no API key needed
```

## core/src — The L1 Kernel

`core/` is AIH's heart — no business logic, no CLI or TUI code. Key files:

| File | Responsibility |
|---|---|
| `agent-loop.ts` | AgentLoop drives multi-step execution per turn, build/plan dual modes, Goal judge |
| `tool-registry.ts` | ToolRegistry guard pipeline: tool registration + permission gate + hooks (redact/timing/audit) + parallel read scheduling |
| `session-log.ts` | SessionLog append-only JSONL event stream, supports fork/checkpoint/restore rollback |
| `seams/` | Replaceable seam interfaces (LLM adapter, sandbox, approval gate, skill loader) |
| `prompts.ts` | System prompt templates (including Goal guard rules) |
| `budget.ts` | Token budget and cost tracking |
| `types.ts` | Core type definitions (Event, Tool, Action, Context, etc.) |

## cli/src — CLI + TUI + Local Tools

`cli/` is the user-facing layer with many files. Highlights:

| File | Responsibility |
|---|---|
| `index.ts` | CLI entry: command parsing, sub-command dispatch (run / chat / tools / serve / attach) |
| `tui.ts` | opencode-style interactive terminal: input rendering, diff display, status bar |
| `config.ts` | Config loading and merging (aih.json / env / CLI flags) |
| `gate.ts` | Approval gate: allow/ask/deny routing, run-or-copy approval |
| `general-tools.ts` | General toolset (read_file / write_file / edit / grep / glob / websearch, etc.) |
| `dev-tools.ts` | Developer tools (shell_context / error-detect / question, etc.) |
| `sandbox.ts` | Sandbox execution backend (local / bwrap / remote) |
| `skills.ts` | Skill loader (SKILL.md three-level loading + BM25 suggestions) |

## mcp-server/src — The L0 Adapter Layer

`mcp-server/` exposes the `AppAdapter` as an MCP server, with just three source files:

| File | Responsibility |
|---|---|
| `app-adapter.ts` | AppAdapter implementation: descriptor + context(query) + actions (zod-defined params) |
| `index.ts` | MCP server startup: registers adapter Context/Action/Event as MCP tools/resources |
| `smoke.ts` | Smoke tests |

`app-adapter.ts` is the best entry point for understanding the L0 contract — it defines a complete todo-app integration that serves as a template for your own adapter.

## Developer Workflow Quick Reference

| Command | Purpose |
|---|---|
| `npm run bootstrap` | Install dependencies |
| `npm run doctor` | Environment check |
| `npm run check` | Build + validate |
| `npm test` | Smoke tests |
| `npm run eval` | Full gate (for CI) |
| `npm run bench` | AIH vs opencode performance benchmark |
| `npm run cli -- <cmd>` | Invoke CLI directly |
